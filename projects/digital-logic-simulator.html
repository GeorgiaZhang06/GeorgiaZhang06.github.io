Digital Logic Simulator

Bare-metal digital logic simulator running on a NIOS-V processor and DE1-SoC FPGA
C C# NIOS-V DE1-SoC MMIO VGA PS/2 GDB

March 2026 – May 2026

In compliance with university academic integrity policies, the source code for this project is not public.

Overview

A bare-metal digital logic simulator written in C and deployed on the NIOS-V processor of the DE1-SoC FPGA board. The simulator builds and evaluates user-defined digital circuits containing combinational and sequential logic, then displays the circuit and wire states on a VGA monitor.

The system was implemented without an operating system or hardware abstraction layer. Peripheral input and output were handled directly through memory-mapped I/O, including VGA, PS/2, LEDs, and HEX displays.

System Architecture

  • Circuit model: represented gates and wires as software structures, evaluated gate outputs from their input wire states, and supported combinational and sequential circuits.
  • Gate builder: parsed compiled circuit data from memory and created the corresponding gates and wire connections at their specified VGA coordinates.
  • Wire routing: automatically connected wires between gates and supported multiple destinations from a single wire.
  • Sequential logic: implemented latch behavior and updated circuit evaluation to retain state between clock cycles.

Compiler

Circuit definitions were written as text files and converted into binary instruction data before being loaded onto the FPGA.

  1. A circuit was described using gate type, wire IDs, and screen coordinates.
  2. A custom C# compiler converted the circuit description into a binary instruction file.
  3. The binary was loaded into FPGA memory at 0x40000000 using GDB.
  4. The NIOS-V program parsed the instructions and constructed the circuit in memory.

VGA & User Input

  • VGA: rendered AND, OR, XOR, NAND, NOR, NOT, and MUX gates and automatically routed wires between circuit elements.
  • PS/2 keyboard: allowed users to select input wires and change their logic values during operation.
  • Wire states: displayed logic values using different wire states on the VGA output.
  • Truth tables: generated truth tables for supported combinational circuits by evaluating every input combination.
  • LEDs and HEX: displayed output states and indicated when a truth table was unavailable.

Hardware Interface

The application interacted directly with FPGA peripherals through fixed memory-mapped addresses rather than relying on an operating system.

  • Wrote pixel data directly to the VGA framebuffer.
  • Polled the PS/2 interface for keyboard input.
  • Controlled LEDs and HEX displays through MMIO registers.
  • Loaded compiled circuit data into SDRAM through GDB.
