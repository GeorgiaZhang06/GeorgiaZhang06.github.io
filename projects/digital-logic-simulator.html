Digital Logic Simulator

Bare-metal digital logic simulator running on a RISC-V processor and DE1-SoC FPGA
C RISC-V MMIO VGA

March 2026 – May 2026

In compliance with university academic integrity policies, the source code for this project is not public.

Overview

A bare-metal digital logic simulator for the RISC-V processor on the DE1-SoC FPGA. Users described circuits in a .log file, loaded them into memory, and interacted with them through PS/2 and VGA.

It supported combinational and sequential logic, live wire-state visualization, input control, and truth tables for smaller combinational circuits.

System Architecture

    The system parsed circuit data, evaluated gate and wire states, and rendered the design directly on the FPGA display.

    • Circuit model: represented gates and wires, evaluated outputs, and supported combinational and sequential logic.
    • Gate builder: parsed compiled data and placed gates and wires at their VGA coordinates.
    • Wire routing: connected gates and supported multiple destinations for each wire.
    • Sequential logic: retained latch state between clock cycles.
    • VGA rendering: displayed gates and wires, using red and green to show logic values.

Project Workflow

  1. The circuit was described in a .log file, with one gate per line.
  2. A custom C# compiler converted the description into binary.
  3. GDB loaded the binary at 0x40000000.
  4. The RISC-V program built the circuit in memory and displayed it on VGA.

Input & Controls

Interrupt-driven PS/2 input enabled navigation and real-time control of circuit inputs.

  • Up / Down: moved between input wires, with the selected wire highlighted in purple and bold.
  • 0 / 1: changed the selected input wire value.
  • Enter: toggled between the home screen and the instruction page.
  • T: displayed a truth table when available.
  • Key 0: reloaded a new circuit from memory location 0x40000000.

Output Displays

  • VGA: displayed the instruction page, the active circuit, or the generated truth table depending on the selected mode.
  • HEX display: showed notbl when a truth table was unavailable, such as for sequential circuits or circuits with too many inputs/outputs.
  • LEDs: displayed the state of the output wires according to each wire index.

Gate Input Format

Each line in the .log file defined one gate:

[GATE TYPE] [INPUT 1 ID] [INPUT 2 ID] [OUTPUT ID] [X COORDINATE] [Y COORDINATE]

For MUX gates, the wire at index INPUT 2 ID + 1 had to be free for the select input.

Hardware Interface

The application accessed FPGA peripherals through fixed memory-mapped addresses.

  • Wrote pixels to the VGA framebuffer.
  • Handled PS/2 input through interrupts.
  • Controlled LEDs and HEX displays through MMIO.
